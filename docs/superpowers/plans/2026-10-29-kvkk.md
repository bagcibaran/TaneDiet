# KVKK Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the KVKK basics for health data:
- a public privacy page;
- versioned, recorded, server-enforced explicit consent;
- dietitian-run export and hard delete;
- 2-year automatic deletion;
- a view log;
- self-hosted fonts.

**Architecture:**
- **Backend:**
  - Legal texts live in a `LegalTexts` class with their versions, served publicly under `/legal/**`.
  - `ConsentService` decides whether a client needs re-consent; `JwtAuthFilter` answers **428** for them.
  - `ClientDataService` does export and transactional hard delete with a `deletion_record`; `AccessLogService` records views; `RetentionJob` (daily, `@Scheduled`) deletes clients whose service ended more than 2 years ago.
- **Frontend:**
  - pages `/gizlilik`, `/consent`, `/clients/:id/export`;
  - a "Veriler ve KVKK" panel on the client page;
  - `apiClient` maps 428 to `/consent`;
  - `@fontsource/inter-tight`.

**Tech Stack:** Spring Boot 4.1 / JPA / Flyway / MySQL, Mockito; React 19 + TS + Tailwind v4.

**Spec:** `docs/superpowers/specs/2026-10-29-kvkk-design.md`

## Global Constraints

- **Legal texts:**
  - Turkish, drafts.
  - Each draft text visibly says it is a draft to be reviewed by a lawyer before going live.
  - Data controller: "Dyt. Betül Bağcı (şahıs)". Placeholders `[ADRES]` and `[E-POSTA]` are filled in by the dietitian.
  - Versions are strings like `"2026-10-29"`.
  - Address clients with "sen".
- **Consent:**
  - Consent hash = SHA-256 hex of the exact consent text, computed on the server.
  - `POST /consent` with a version other than the current one → 409.
- **Re-consent rule:**
  - CLIENT **with an intake form** whose latest `consent_record.version` ≠ current → **428** on every request except `/consent/**`, `/legal/**` and `/auth/**`.
  - Clients without an intake form are never 428'd: first consent comes from the intake form.
- **Retention:**
  - Auto-delete a CLIENT when `access_until < today − 2 years` (Istanbul clock); never when `access_until IS NULL`.
  - Purge `access_log` entries older than 2 years.
- **Deletion:**
  - Hard delete in one transaction.
  - The typed confirmation must equal the client's username exactly, else 400.
  - `deletion_record` keeps only the client id, deleted_at, deleted_by_id (null for automatic) and reason `REQUEST` | `RETENTION`.
- **View log:**
  - Actions `VIEW_INTAKE` (dietitian GET `/clients/{id}/intake`) and `EXPORT`.
  - Never log answers or contents.
- **Frontend:**
  - Confirm with `useFeedback`; theme tokens only; `usePageTitle`; TR/EN chrome; works at 375 px.
  - Self-hosted Inter Tight weights 400–800. No `fonts.googleapis.com` in `index.html`.
- **Working agreement:** Claude writes the code, and the user commits. Never run `mvnw clean` while the user's backend may be running.

## Review Focus

1. **Deleting a client that has every kind of data** (weights entered by both sides, plans with meals, review, consent, logs, a used invite, tasks) succeeds with no FK error, and nothing remains. Covered by curl in Task 5 against a seeded client.
2. **Failure mid-deletion** rolls everything back. `deleteClientData` is `@Transactional`; Task 3's test checks `deletion_record` is saved last.
3. **The 428 must not trap a client:** `/consent`, `/legal` and `/auth` work for a gated client, and the consent page loads and accepts. Covered by Task 2's filter tests and Task 6's browser check.
4. **Old clients with only `consent_given_at`** are gated exactly once, then pass. Covered by Task 1's `ConsentServiceTest.oldClientWithoutRecordNeedsConsent`, plus Task 6's browser check.
5. **Retention edge:** a client whose `access_until` is exactly 2 years ago is kept; one day older is deleted. Covered by Task 4's `RetentionJobTest.boundary`.

**Interfaces:**
- `RetentionJob(UserRepository, ClientDataService, AccessLogRepository, Clock)`.
- `run()`:
  - `cutoff = today.minusYears(2)`;

  - each client is deleted in its own transaction, so one failure does not stop the others.
